1. Qué es el proyecto

No es solo una IA, ni un dashboard, ni un conjunto de prompts. Es una máquina de producción de artefactos que cierra el vacío entre información y acción. Toma algo abstracto y lo convierte en algo útil, verificable, exportable y con continuidad.

Problema que resuelve

Las conversaciones con IA suelen morir en la respuesta. Los dashboards muestran datos, pero no deciden. PraxioGraph conecta respuesta, evidencia, decisión, artefacto, acción y aprendizaje.

Unidad de valor

La unidad de valor es el artefacto accionable: ebook, ficha, brief, mapa narrativo, imagen educativa, prompt pack, landing, protocolo o matriz.

Regla central

Cada artefacto debe tener evidencia, validación, acción, aprendizaje y descendencia. Si un output no activa nada ni deja aprendizaje, es un output muerto.

Intención→Evidencia→Significado→Artefacto→Acción→Aprendizaje→Descendencia

2. Términos base

El término correcto es PraxioGraph, no “Praxios”. Es un concepto para nombrar un grafo de realidad accionable: una red donde cada intención, evidencia, regla, artefacto, acción y aprendizaje queda conectado.

PraxioGraph = grafo de realidad accionable.

Praxis = acción situada / práctica / intervención.
Graph = red de nodos y relaciones.
OS = sistema operativo.

PraxioGraph OS = sistema operativo que convierte intención, datos o señales en evidencia, significado, artefacto, acción, aprendizaje y descendencia.

Glosario mínimo

Meta System: capa que crea sistemas, agentes, skills, ontologías, prompts, pipelines, tests y releases.

PraxioGraph OS: sistema operativo de realidad accionable.

Ontology OS Layer: capa semántica interna. Define términos, clases, relaciones y constraints.

Artifact Workbench UI: cabina visual donde nacen, se validan y se escalan artefactos.

Artifact Lineage: descendencia del artefacto.

4. Motores internos de PraxioGraph OS

Estos motores convierten la arquitectura en operación. Cada motor tiene una función clara y debe tener representación visual dentro de la UI.

Ontology OS Layer

Define significado: clases, términos, relaciones, sinónimos, mappings y constraints. No es el sistema superior; vive dentro de PraxioGraph OS.

Evidence Ledger

Registra fuente, evidencia, confianza, limitación y estado de verificación. Evita convertir hipótesis en verdad.

Policy Gate

Permite, bloquea o exige revisión humana. Publicar alertas, lanzar ofertas o declarar validaciones requiere gate.

Workflow Engine

Convierte decisiones en tareas: owner, estado, prioridad, bloqueo, revisión y seguimiento.

Artifact Factory

Genera outputs concretos: fichas, briefs, ebooks, landings, prompt packs, mapas, protocolos, mensajes o reportes.

Learning Loop

Registra qué funcionó, qué falló, qué regla actualizar, qué métrica observar y qué debe mejorar.

Lineage Engine

Obliga a que cada artefacto tenga descendencia: derivados inmediatos, comerciales, operativos, learning y system.

        SDD

        Specification-Driven Design. Antes de construir se define dominio, dolor, usuario, artefacto, evidencia, validación, acciones, learning, descendencia, componentes y tests.

        TDD

        Test-Driven Development. No se declara éxito porque “se ve bien”. Debe pasar tests de artefacto central, evidencia, validation, action queue, learning, descendants y export.

        Semantic CI

        Checks contra drift conceptual: no confundir Ontology OS con sistema superior, no crear dashboard muerto, no borrar lineage, no presentar mock como producción.

        8. Agentes, skills y meta-skills

        9. Diferenciador

        El diferenciador no es “usa IA”. El diferencial es que la IA queda gobernada por evidencia, ontología, policies, workflow, UI operativa, aprendizaje y descendencia.

        SistemaQué haceLímiteDiferencia PraxioGraph
        ChatGPT / Claude normalPregunta → respuesta.La conversación muere si no hay estado, workflow ni artefactos.Convierte respuestas en artefactos, acciones, learning y descendencia.
        DashboardDatos → gráficos.Muestra indicadores, pero no necesariamente decide ni actúa.El artefacto central, action queue y learning reemplazan el tablero pasivo.
        RAGDocumentos → respuesta contextual.Puede responder bien, pero no siempre genera acción o productos derivados.Usa evidencia como parte de un ciclo de producción y validación.
        Agente genéricoObjetivo → acciones automáticas.Riesgo de actuar sin gates, evidencia o trazabilidad.Policy Gate y Human Review controlan acciones sensibles.
        PraxioGraphIntención → evidencia → artefacto → acción → aprendizaje → descendencia.Requiere diseño y disciplina; no es magia automática.Produce activos útiles, trazables, reutilizables y potencialmente vendibles.

        10. Anti-humo: qué bloquea el sistema

        El sistema se vuelve humo si solo produce abstracción, pantallas bonitas o promesas. Por eso necesita gates duros y reglas de bloqueo.

        Debe bloquearse si falta

        • Artefacto central.
        • Evidencia o fuente.
        • Validación.
        • Action queue.
        • Learning record.
        • Descendant tree.
        • Export o salida reutilizable.
        • Human review para acciones sensibles.

        Regla brutal

        Si una idea no modifica una clase, relación, regla, workflow, métrica, artefacto, decisión, acción o aprendizaje, probablemente es discurso.

        Esto evita que el Meta System se transforme en una nube de conceptos sin implementación.

        12. Cómo está construido técnicamente

        La primera versión se puede construir como app local con estado determinístico. La IA ayuda a construir y luego puede entrar como motor cognitivo, pero no debe reemplazar la memoria, la policy ni los tests.

        Frontend

        React + TypeScript. Componentes: ExecutionHeader, PipelineRail, CentralArtifactCanvas, RightInspector, BottomDock.

        Engine

        praxioEngine, policyEngine, lineageEngine, exportEngine y validationEngine.

        Datos

        Domain registry, execution records, artifact records, evidence, actions, learning y descendants.

        Tests

        Vitest, smoke tests, check_pack, check_glossary y anti-humo checks.

        13. Preguntas críticas

        No. Claude o ChatGPT pueden ser motores cognitivos. PraxioGraph es la arquitectura que los gobierna: estado, evidencia, artefactos, acciones, learning y lineage.

        No. Ontology OS Layer es una capa semántica interna. PraxioGraph OS es más amplio: incluye evidencia, policies, workflows, artifact factory, learning y lineage.

        Porque la UI no existe para mirar datos, sino para hacer nacer artefactos, validarlos, corregirlos, activar acciones y generar descendencia.

        El camino más rápido es Ebook Revenue Workbench: convertir conocimiento en ebook, plantilla, prompt pack, landing, posts y consultoría express.

        Después. Primero construye local con Claude Code y Max 5x. La API tiene sentido cuando el sistema deba operar como producto para terceros.
